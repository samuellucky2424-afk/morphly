# Morphly Desktop 2.5.2

## Included

- Approved white/red appearance throughout the desktop app, authentication forms and admin portal, retaining the existing dashboard arrangement.
- Correct signup outcomes for existing and unconfirmed email addresses, with persistent inline feedback instead of false account-created messages.
- Verified password-recovery links, isolated recovery sessions, expired-link handling, retryable errors and a clear return to sign-in.
- Customer reviews, dismissible maintenance/update announcements, admin feedback management and queued Resend customer emails.
- Checked virtual-camera repair in Settings and improved camera registration preservation during updates.
- Bounded voice buffers, lower requested driver latency, live-processing diagnostics and model warm-up without microphone access.

## Validation

- 145 Node regression tests and seven mocked Python audio-buffer tests.
- TypeScript, production web build and isolated browser checks for the affected forms and interfaces.
- Native camera build and installer macro checks; see the limitations below.

## Deployment requirements and known limits

- Customer communications require the database migration and server-only Resend/cron configuration described in `docs/customer-communications.md`. Publishing the app does not activate these services by itself.
- Password recovery requires the Supabase redirect allowlist and Auth email configuration in `docs/auth-recovery.md`. Real email delivery and a designated-account reset must be checked after deployment.
- Camera registration must still be accepted on clean and upgraded affected Windows devices, including WhatsApp. Windows Application Control blocked the final unsigned helper on the development machine; no security policy was bypassed.
- Voice measurements used synthetic audio. Real microphone/output quality and performance on the affected laptop still require acceptance testing; performance depends on available processing capacity.
- A Git tag starts the release workflow. The Windows installer is published only after the workflow builds and verifies its bundled camera and voice artifacts.

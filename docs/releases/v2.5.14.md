# v2.5.14 — CPU voice performance

Local voice conversion now uses dynamic INT8 VC inference and measures available CPU headroom before opening audio devices. Slower CPUs automatically use fewer inference steps to keep pace with live speech. Unsupported INT8 conversion falls back to floating-point models.

The reference-speaker model loads only while extracting a voice embedding and is released before live conversion. Worker warmup completes before microphone capture starts. Existing bounded audio queues prevent a growing backlog.

On the affected i5-1135G7, the optimized 60-second synthetic test completed without dropped input/output blocks, with one startup underrun. Its final processing window measured 114.5 ms mean / 119.5 ms p95 per 160 ms audio block. Tests also covered reference loading and pitch changes. Lighter inference can affect voice fidelity; actual device latency and listening quality remain separate checks.

The release adds CPU regression tests to CI and a backed-up administrator patch helper for local installations. See `docs/voice-cpu-performance.md` for benchmark details and reproduction commands.

This release carries the CPU performance changes on top of v2.5.13. Experimental translation and other uncommitted work in the development export are not part of this tag.

To: platform@vidu.com
Subject: Morphly S2-Editing: intermittent browser WebSocket failures before initialization

Hello Vidu Platform Support,

We integrate Vidu S2-Editing into Morphly for real-time camera transformation. Several users report intermittent startup failures. Please investigate the sessions below and advise on a supported, reliable configuration.

Our flow:
- Server creates a session using POST https://api.vidu.com/live/s_editing/realtime, with a server-only API key and a reference image.
- The browser uses the returned client_secret at wss://api.vidu.com/live/ws/live/connect with live_id and a UUID conn_id.
- On opening the socket we send conn_init (type 1, version 1), then join AliRTC and publish the selected camera after successful initialization.
- Failed signaling handshakes now retry up to three times, reusing the same live_id and conn_id.

Observed failure:
The browser reports a WebSocket connection failure with no visible HTTP status or response headers. In the earlier captured failure, initialized=false, published=false and receivedVideo=false. No conn_init acknowledgement was observed. Browser: Microsoft Edge 154 / Chromium 154, Windows 10. Tracking-prevention warnings were also present, but we have not established whether they caused the failure.
